# Sky WebSocket Chat

**Status: engineering beta.** This repository contains a focused TypeScript/Socket.IO real-time room-chat service. GitHub Actions verifies the strict TypeScript build, socket/API tests, runtime dependency audit, Docker build, non-root image user, and an HTTP health smoke test. Production deployment is not verified here.

## Implemented behavior

- Socket.IO room joins with UUID room identifiers.
- Bounded user identifiers and message content.
- A connection is bound to one declared user identity and cannot switch identities mid-session.
- A socket must join a room before it can publish into that room.
- Message timestamps and sender identity are generated by the server rather than trusted from the client payload.
- Membership is removed on leave/disconnect.
- Request/message payload size is bounded by Socket.IO.
- Optional explicit CORS origin allow-list via `CORS_ORIGINS`.
- `/healthz`, `/readyz`, and lightweight `/metrics` endpoints.
- Non-root container runtime.

## Run locally

```bash
npm ci
npm run build
npm test
npm start
```

The service listens on port `3000` by default. Override it with `PORT`.

For browser clients hosted on other origins, provide an explicit comma-separated allow-list:

```bash
CORS_ORIGINS=https://app.example.com,https://admin.example.com npm start
```

## Socket contract

Join a room:

```json
{"roomId":"123e4567-e89b-12d3-a456-426614174000","userId":"alice"}
```

Event: `join_room`

Send a message after joining:

```json
{"roomId":"123e4567-e89b-12d3-a456-426614174000","content":"Hello"}
```

Event: `send_message`

Successful broadcasts use `new_message` and include server-authored `userId` and `timestamp` fields. Policy/validation failures use `chat_error` with a stable error code.

## Architecture

The current service is intentionally single-node. Membership state is process-local in memory; Socket.IO owns transport/session mechanics and Express exposes operational endpoints. No Redis adapter or persistence layer is claimed.

A future multi-instance deployment should use a tested Socket.IO adapter or another broker-backed fan-out layer instead of pretending this in-memory map is distributed state.

## SKYCOIN4444 integration

SkyChat, live feeds, creator rooms, gaming sessions, classrooms, or other real-time modules can consume this service through the Socket.IO contract. Authentication and authorization should be added at the connection/join boundary using Sky Identity or another verified identity layer. The standalone repository should remain independently deployable rather than being copied wholesale into a flagship codebase.

## Security and limitations

This beta validates transport payloads and room membership, but it does **not** currently provide authentication, authorization, moderation, durable message history, end-to-end encryption, tenant isolation, distributed presence, rate limiting, spam protection, HA, or a verified production deployment. TLS is expected to terminate at trusted ingress infrastructure.

See `SECURITY.md` for reporting and deployment boundaries.
